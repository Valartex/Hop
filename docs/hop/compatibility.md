Это подтверждает работу транспорта в текущей сети, но не системного VPN/Kill Switch.

## Amnezia vpn://

Ключ из запроса декодируется как URL-safe base64, затем 4-байтовый префикс
и zlib-содержимое JSON. JSON содержит `config_version`, `api_config`, `auth_data.api_key`.
Следовательно, это доступ к API сервиса, а не готовый адрес/ключ VPN-сервера.
14 октября API приняла ключ и вернула каталог 53 стран. Первоначальная выдача
конфигурации была отклонена кодом 1108 из-за лимита подписки. После освобождения
пользователем слота системное подключение AWG 3.1 в Windows VM прошло HTTPS по IP,
HTTPS с DNS и явный UDP DNS; временная конфигурация успешно отозвана.
[Результаты и ограничения](windows-awg-validation-2026-10-14.md).

У конкретного примера префикс равен `00 00 00 FF`, а распакованный JSON занимает
258 байт. В `client/core/utils/api/apiUtils.cpp` этот префикс называется
`AMNEZIA_CONFIG_SIGNATURE` и намеренно заменяет исходный префикс длины `qCompress`.
Это маркер формата, а не достоверная длина и не криптографическая подпись.
Декодер должен ограничивать фактический размер распаковки и не требовать равенства
размера JSON числу 255. Секретные значения не сохранялись в файлах.

[Генерация ключа в базовой ревизии](https://github.com/amnezia-vpn/amnezia-client/blob/3e8077f2cae9ba7046a99025e303351e0fd31a8e/client/core/utils/api/apiUtils.cpp).

## Маршруты geo-for-ru-only

Публичные артефакты загружены по ссылкам пользователя и прочитаны как protobuf:

| Файл | Размер | Содержимое | SHA-256 |
| --- | ---: | --- | --- |
| geoip.dat | 351 134 байта | `PRIVATE`: 18 CIDR; `RU`: 22 983 CIDR | `48b8e1e2118026ac5d53a6ab01774b6392717d640146d3b4851cf8fc9882e72d` |
| geosite.dat | 81 911 байт | Категории, в том числе `CATEGORY-RU`, `TLD-RU`, `YANDEX`, `VK` | `2ca7401262e88769999629309fdde61d862aef7ed67583fe7325d348876e9eaa` |

Наличие `RU` в GeoIP не означает наличие одноимённой категории в GeoSite.
Окно импорта должно отображать категории фактически загруженного файла.
14 октября оба файла также загружены и проверены нативным контроллером Hop:
совпали SHA-256, обнаружены 2 категории GeoIP и 81 категория GeoSite.
Импорт/каталог доступны в интерфейсе; применение к VPN ещё не реализовано.

[Репозиторий наборов](https://github.com/kepler103b/geo-for-ru-only),
[сборка форматов](https://github.com/kepler103b/geo-for-ru-only/blob/main/.github/workflows/build.yml).

## Среда разработки

14 октября 2026 подготовлены Qt 6.10.1 MSVC x64, Visual Studio 2022 Build Tools
(MSVC 19.44.35229), Windows SDK 10.0.26100, CMake 3.31.10, Conan 2.33.0,
Ninja 1.13.2. Полностью собраны `Hop.exe` и `Hop-service.exe`.
Conan разрешил зависимости, включая libagw 1.0.6, AWG Windows 3.1.20260814,
amnezia-xray-bindings 1.4.0, Wintun 0.14.1 и tun2socks 2.6.0.
Пройдены тесты политики выбора, парсера/сопоставления подписок, репозитория
и главного QML-экрана с настоящими C++-контроллерами.
Qt HTTPS-загрузчик получил и проверил все 62 записи предоставленной подписки.
Запуск Hop из каталога с DLL прошёл без ошибок загрузки QML.
На хосте служба/драйверы Hop не установлены. Тест системного Xray в Windows 10 VM
создал TUN/маршруты, но HTTPS завершился тайм-аутом (Qt 4, exit 3).
Системный VPN и аварийный Kill Switch не приняты.

Повторный тест в 18:39 МСК прошёл: все четыре HTTPS-этапа HTTP 204 / Qt 0,
exit 0. Базовый тракт VLESS/TUN и штатное восстановление сети проверены;
аварийный Kill Switch, DNS/IPv6-утечки, UDP, GUI/SCM и AWG ещё не приняты.
[Подробности и последующие исправления](vm-validation-2026-10-14.md).

В последующей сборке 14 октября исправлен пропущенный путь импорта HTTPS
в `PageSetupWizardConfigSource`, который давал ErrorCode 900. Все три формы
ввода используют общий обработчик `ConnectionImport.prepareConnectionImport`.
Регрессионный тест воспроизводит нажатие кнопки на настоящем стартовом экране.

Для Hop заданы собственные имена `Hop`, `Hop-TUN`, `AmneziaWGTunnel$Hop`
и WFP UUID. IPv6 ограничивается собственными динамическими фильтрами,
а не удалением глобальных маршрутов. Драйвер разделения приложений upstream
не создаётся. Эти изменения скомпилированы, но ещё требуют сетевой проверки в VM.
Привилегированные процессы запускаются без завершения всех одноимённых процессов;
аргументы с SOCKS-паролем больше не выводятся в лог.

Позднее добавлен отдельный `hop_endpoint_probe`: аутентифицированный локальный
SOCKS, один VLESS-выход без Direct-fallback, HTTPS 204, общий тайм-аут 12 секунд.
На первой Reality-записи получен HTTP 204 за 381 мс; полный проход по 62 записям
дал 50 успешных и 12 без ответа, медиана успешных 584 мс. Измерения проходили
с активной Amnezia на хосте. Они не доказывают доступность серверов из другой сети
или напрямую без текущего VPN и не измеряют пропускную способность.
Проверка закрытого синтетического VLESS-адреса `127.0.0.1:9` корректно завершилась
ошибкой, без успешного прямого HTTPS.

Исправлены учёт чужих маршрутов в очистке, полная инициализация MIB_IPFORWARDROW,
выбор исходящего маршрута к серверу и отдельный IPv4 /32-обход собственного TUN.
Ошибка удаления маршрута сохраняет запись для повторной очистки.
[GetBestRoute](https://learn.microsoft.com/en-us/windows/win32/api/iphlpapi/nf-iphlpapi-getbestroute),
[CreateIpForwardEntry](https://learn.microsoft.com/en-us/windows/win32/api/iphlpapi/nf-iphlpapi-createipforwardentry).
Эти изменения собраны, но требуют повторного сетевого запуска в VM.
