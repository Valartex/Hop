# Архитектура

## Выбранный путь

Используется исходный клиент Amnezia: C++ / Qt 6 / QML, CMake / Conan,
его VPN-службы и интеграция Xray/AmneziaWG. Решение согласовано после уточнения,
что GPL и публикация исходников допустимы. Flutter не даёт готового системного
VPN-слоя: выигрыш нового UI пришлось бы оплачивать повторной реализацией
платформенных служб, маршрутизации и жизненного цикла туннелей.

Это инженерный выбор по объёму интеграции. Превосходство Qt по RAM, CPU или
батарее пока не измерено и не заявляется.

Источники: [upstream](https://github.com/amnezia-vpn/amnezia-client/tree/dev),
[Flutter platform integration](https://docs.flutter.dev/platform-integration).

## Слои

1. QML представляет сервисы, локации, состояния и настройки. UI не хранит ключи
   и не управляет системными маршрутами.
2. Модели Qt предоставляют объединённый каталог локаций всех сервисов. Отдельно
   хранятся постоянные настройки пользователя и обновляемые данные провайдера.
3. Адаптеры источников нормализуют HTTPS-подписки, Amnezia API и статические файлы.
   Нормализованные endpoint сохраняют необходимые протокольные параметры без потерь.
4. Контроллер соединения сериализует команды connect/disconnect/reconfigure,
   использует политику выбора и координирует нативную службу.
5. Нативный слой отвечает за VPN-ядра, маршруты, DNS, firewall/Kill Switch,
   восстановление после сбоя и сна. Переключение продолжает работать при скрытом UI.

Чистая политика выбора не имеет доступа к сети или Qt. Она возвращает решение;
исполнитель проверяет поколения конфигурации и соединения, прежде чем применить его.
Отложенный результат от старой проверки не должен переключать уже новое соединение.

## Протоколы и маршруты

VLESS Reality обслуживается Xray. AmneziaWG 3.1 — совместимым ядром AmneziaWG.
Поддержка обычного WireGuard или AWG 2.0 не считается поддержкой 3.1.
Параметры `HeaderProtectionKey`, `ContentPaddingAddition`, диапазоны таймеров,
`RandomTrailers`, `DisableCookies` сохраняются при импорте и обновлении.

[Описание 3.1](https://docs.amnezia.org/documentation/amnezia-wg/),
[UAPI amneziawg-go](https://github.com/amnezia-vpn/amneziawg-go/blob/master/device/uapi.go).

DAT — protobuf-наборы данных маршрутизации, а не готовая политика Direct/VPN.
Направление и приоритет задаёт пользователь. Для Xray используются его штатные
механизмы GeoIP/GeoSite. Для AWG требуется отдельная проверка общего механизма
доменной маршрутизации: копирование имени DAT в конфигурацию WireGuard не работает.
Этот пункт — обязательный интеграционный этап, а не уже реализованная функция.

[Маршрутизация Xray](https://xtls.github.io/config/routing.html).

Импорт DAT: ограничение размера и времени, проверка структуры и категорий,
SHA-256 для диагностики версии, сохранение во временный файл и атомарная замена.
Хэш без доверенной подписи не доказывает авторство набора. Обновления выполняются
в фоне с кэшем; старые рабочие правила остаются при ошибке новых.

Текущее состояние: `client/core/routing/geoData.*` проверяет bounded protobuf
и строит индекс по смещениям, сохраняя один исходный буфер. Категория разворачивается
в строки лишь при компиляции. Сохраняются IPv4/IPv6 и четыре типа доменов Xray;
`reverse_match` распознаётся и явно отклоняется компилятором, пока не реализовано
дополнение множества. `RouteDatasetsController` загружает HTTPS/локальные файлы,
разбирает их через QtConcurrent и атомарно сохраняет QSaveFile. Сейчас UI только
сохраняет и просматривает наборы; активная маршрутизация не меняется.
[Схема Xray](https://github.com/XTLS/Xray-core/blob/main/common/geodata/geodat.proto).

## Подписки

Идентификатор источника не зависит от его отображаемого имени. У endpoint нужен
стабильный ID внутри источника, не основанный только на позиции в ответе или подписи.
Изменение адреса или ключа не должно автоматически стирать выбор пользователя.
При отсутствии стабильных ID провайдера нужен явный алгоритм сопоставления и
разбор неоднозначностей, а не догадка по совпавшему названию.

Обновление — транзакция: загрузка, проверка, нормализация, сопоставление, фиксация.
Удалённые узлы исключаются из новых попыток, а текущий туннель управляемо завершается
или заменяется. HTTP 200 с HTML-страницей ошибки не считается пустой подпиской.
ETag/Last-Modified, Retry-After, экспоненциальная задержка со случайной добавкой;
таймеры фонового обновления подчиняются ограничениям мобильной ОС.

Ключ Amnezia API не является статической конфигурацией VPN. Нужны доступные API,
совместимая авторизация и обновление выданных конфигураций. Публичность клиента
не гарантирует доступность всех инфраструктурных параметров стороннему форку.
Проверка реального API-доступа отдельно от проверки формата ключа обязательна.

Реализация первого HTTPS-адаптера находится в `client/core/subscriptions/`.
Для сопоставления сначала используется точное совпадение URI без отображаемой
подписи, затем уникальная подпись вместе с транспортом и security внутри источника.
Это сохраняет ID при переименовании либо смене адреса/ключа с прежней подписью.
Неоднозначность отменяет обновление. Если провайдер одновременно изменил подпись
и конфигурацию, запись считается новой: универсального стабильного ID в VLESS URI нет.
Источник и служебные метаданные сериализуются в `hopSubscription` внутри
зашифрованного `Servers/serversList`; отдельного plaintext-файла подписок нет.
Фоновый таймер проверяет срок обновления раз в минуту, период подписки — 6 часов.
Операции сериализованы, одновременно загружается одна подписка.
Пакет репозитория валидируется полностью и записывается одним зашифрованным значением
настроек через проверяемый `SecureQSettings::setValueChecked`. Обновлённая модель
публикуется после успешной синхронизации; инъекция отказа записи проверяет сохранение
старого снимка. Аварийное выключение Windows во время записи ещё не проверено.

## Системные ограничения

- Windows: привилегированная служба, драйверы, подпись пакета, WFP и восстановление
  маршрутов. Hop должен иметь собственные IPC, ключи хранилища и идентичность службы,
  чтобы сосуществовать с установленной Amnezia. Массовый поиск/замена названия опасен.
- Linux: служба с минимальными привилегиями, TUN, policy routing, DNS разных окружений.
- Android: VpnService, исключение сокетов транспорта, foreground service и смена сети.
- macOS/iOS: Network Extension, entitlement, подпись и сборка на Mac. На обычном iOS
  нельзя обещать пользовательский выбор любых приложений как на Android.

[Android VPN](https://developer.android.com/develop/connectivity/vpn),
[Apple Network Extension deployment](https://developer.apple.com/documentation/technotes/tn3134-network-extension-provider-deployment).

## Маскировка и доступность

Reality/AWG меняют наблюдаемые признаки трафика, но не создают сетевой путь
к заблокированному IP. Профили для ограниченных сетей должны опираться на серверы
и транспорт провайдера. UI показывает протокол и результат проверки такого профиля,
не подставляет произвольный разрешённый домен с обещанием обхода.

Проверка порта не заменяет проверку туннеля. Для AWG проверка TCP-порта вообще
не является корректной проверкой его UDP-транспорта. Нужна авторизованная проверка
через соответствующий протокол, ограниченная по частоте и трафику.

Текущее состояние Windows: `EndpointHealthController` запускает до двух
короткоживущих `hop_endpoint_probe` по ручному запросу. Конфигурации передаются
через stdin, в очереди хранятся только ID, stderr не пересылается в журнал UI.
Каждый помощник создаёт собственный Xray/SOCKS с одноразовым паролем и проверяет
HTTPS 204. Тесты устаревают через две минуты; изменение каталога отменяет очередь
и работающие процессы, чтобы не принимать результаты старой конфигурации.
Ручная пакетная проверка охватывает нативные VLESS и текущий системный маршрут.
Рабочий `LocationCoordinator` отдельно проверяет DNS через активный собственный TUN,
ждёт ACK очистки и последовательно подключает разрешённых кандидатов. В VM проверен
переход AWG 3.1 → BlancVPN VLESS Reality с сохранением WFP-защиты между попытками.
Проверки всех кандидатов через отдельный uplink одновременно с рабочим VPN,
физическая смена сети и сон ещё требуют приёмки.
