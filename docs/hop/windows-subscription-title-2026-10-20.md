# Отступ секции и название подписки — 0.2.0.7

## Поведение

Заголовок подписки сохраняет высоту 56 px. Контейнер секции добавляет снизу
тот же отступ, что установлен между локациями (8 px). У Qt ListView обычный
spacing не создавал зазора между section.delegate и первой строкой. Правая
координата кнопки меню по-прежнему совпадает с кнопками локаций.

Название определяется по данным, без таблицы соответствий доменов провайдерам:

1. Явное пользовательское имя сохраняется.
2. При автоматическом имени используется корректный HTTP `profile-title`.
3. Если при обновлении нового заголовка нет, сохраняется прежнее известное имя.
4. Если названия ещё нет, используется hostname источника.

Проверка HTTP-ответа по ранее предоставленной подписке BlancVPN дала HTTP 200
и `profile-title` в формате `base64:…`, декодируемый в `BlancVPN`. Тело/ключ
подписки в отчёт не записывались. Запрос был только чтением HTTP-заголовка,
без изменения VPN/маршрутов основного ПК. Проблема оказалась в отсутствии чтения
этого заголовка клиентом; сам по себе fallback на hostname корректен.

Поддержаны обычный UTF-8 и `base64:` с UTF-8. Заголовок ограничен по длине,
повреждённая кодировка и управляющие символы отбрасываются. Ошибка необязательного
названия не отменяет корректную загрузку серверов. Заголовок передаётся из
изолированного загрузчика в контроллер и применяется также при HTTP 304.
Текст заголовка диалога отображается как PlainText.

Поле metadata.sourceNameMode различает custom и automatic для следующих
обновлений. Для старых записей без этого поля сохранённый hostname считается
автоматическим, другое непустое имя — пользовательским. В старой схеме невозможно
отличить специально введённый hostname от такого же значения по умолчанию.
При фоновом обновлении введённое пользователем имя в очереди не заменяется
старым автоматическим значением.

Существующую подписку не нужно удалять: обычное «Обновить» получает название.
Офлайн-переименования по домену и принудительной загрузки конфигураций нет.
Приоритеты, ID локаций, подключение и маршрутизация из-за имени не меняются.

Механизм profile-title описан в
[документации Happ](https://www.happ.su/main/ru/dev-docs/app-management).
Поддержка других управляющих заголовков в эту правку не добавлялась.
