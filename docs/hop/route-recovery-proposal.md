# Восстановление маршрутов после аварии службы

Статус: пользователь отдельно разрешил реализацию и проверку в VM. После этого
патч применён; сборка и системная проверка ожидаются. Первоначальный отказ
автоматической проверки не обходили; до разрешения файлы реализации не создавали.

Предлагаемый точный объём:

1. Служба записывает только маршруты, для которых её CreateIpForwardEntry вернул
   успех. Существующие до подключения маршруты не присваиваются Hop.
2. Журнал `%ProgramData%\Hop\routes-v1.json` хранит полную строку IPv4-маршрута,
   LUID/GUID интерфейса и идентификатор текущей загрузки Windows; секретов там нет.
   Каталог доступен только SYSTEM/Administrators, без reparse points; замена файла
   атомарная. Блокировка исключает одновременных писателей.
3. Для идентификатора загрузки — собственный volatile-ключ
   `HKLM\SOFTWARE\Hop\RouteJournalBoot`, исчезающий после перезапуска ядра Windows.
   Записи предыдущей загрузки не дают права удалять маршруты новой.
4. При запуске службы и штатной очистке удалить только записанные строки, которые
   полностью совпадают с текущими (адрес, маска, шлюз, интерфейс, policy, protocol,
   type, все метрики). Изменённые другим участником строки не удаляются.
   Повреждённый/недоступный журнал запрещает новые изменения маршрутов.
5. При невозможности сохранить новую запись — отменить только что созданный маршрут
   и сообщить об ошибке подключения; блокировки WFP остаются активными.
6. Удаление MSI и VM recovery очищают тот же собственный журнал после остановки службы.

Ограничение: Windows не выдаёт отдельный owner token для маршрута. Если другой
администратор заменит запись абсолютно идентичной, отличить её от записи Hop
невозможно. Внезапная авария между созданием маршрута и сохранением журнала также
остаётся узким окном; это не обещание абсолютно полной очистки при любом отказе.

Проверка — только через ограниченный агент Windows 10 VM: создать свои тестовые /32,
оставить сторонний контрольный /32, аварийно завершить собственную службу, проверить
восстановление и сохранение стороннего маршрута. На основном ПК службу не запускать,
HKLM/ACL/маршруты не изменять. Коммитов и публикации не выполнять.
