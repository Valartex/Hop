# Замечания 21 октября: автопереключение, скорость, Amnezia

Рабочая версия: 0.2.0.10. До проверки кандидат не считать установленным на основном ПК.
Другие платформы, MSI и обход белых списков не входят в эту работу.

## Согласованный запрос

- Название подключённой локации в системном уведомлении.
- Два режима по всем локациям: порядок списка с порогом задержки и минимум задержки.
- Входящая/исходящая скорость в Мбит/с, по возможности VPN и напрямую.
- Режим маршрутизации внутри карточки текущего подключения.
- Собственная идентичность службы в диспетчере задач.
- Подсказка «Проверить» содержит только описание действия.
- Устранить бесконечную попытку подключения Amnezia; исследовать реальный отказ.
- Не показывать подпись «Исключена из автопула» после удаления из пула.

## Реализация

Сохранены номера существующих режимов Manual/Pinned/Automatic; добавлены AllOrdered
и AllFastest. Исключения учитываются и в режимах всех локаций. В режиме порядка
перебор продолжается после последней работавшей локации и оборачивается в начало.
Новая локация должна подтвердить задержку не выше порога через свой туннель.
Рабочая локация сохраняется до срабатывания существующего условия переключения.
Окно наблюдения и обновление подписки до переключения сохраняются.

Режим минимума использует свежие доступные замеры. В начале сессии допустима
ограниченная предварительная проверка; после остановки сбойного туннеля используются
имеющиеся результаты, потому что сохранённый Kill Switch блокирует обычные внешние
пробы. Эти блокировки нельзя выдавать за отказ всех серверов. Получение профилей
всех стран API ради замеров не выполняется: каталог Amnezia не содержит endpoint.
Следовательно, глобальный минимум среди ещё не измеряемых стран не гарантируется.
Это ограничение описано в UI; новая локация проверяется через собственный туннель.

Скорости берутся из outbound-счётчиков Xray hop-vpn/hop-direct через loopback
metrics. Обновление раз в секунду, не более одного HTTP-запроса одновременно,
тайм-аут 1,5 с, ограниченный размер ответа. Мбит/с = deltaBytes * 8 / deltaSeconds /
1 000 000. Сброс счётчика не превращается в огромную скорость. Нет ответа — «—».
Общий frontend используется также для AWG с маршрутами. «Напрямую через Hop»
исключает трафик системных маршрутов, обходящий frontend, например PRIVATE LAN.
Счётчики всего сетевого адаптера не используются как якобы точная разница VPN/Direct.
Основание API: https://xtls.github.io/config/metrics.html и локальный исходник
amnezia-xray-core v1.260728.0 app/metrics/metrics.go.

Создание интерфейса AWG больше не означает подтверждённый обмен с сервером:
ручной режим тоже проходит Verifying. Запуск транспорта/начальная проверка ограничены
30 с (подготовка API имеет отдельный существующий предел 90 с). Отсутствие ответа
на начальной проверке не переводится в бесконечное наблюдение задержки рабочего
туннеля. Неожиданный Disconnected считается отказом попытки. Терминальная ошибка
передаётся в UI; неподтверждённая очистка после отказа повторяется с сохранением
защиты. Это не меняет принятую область действия Kill Switch.

Системный успех сообщается после подтверждённого ответа и содержит имя локации.
Повторный Healthy не создаёт одинаковое уведомление каждые 15 с. PE-описание службы
исправлено на Hop Service; собственная зарегистрированная служба была отдельной и
раньше. Прочитанные на основном ПК PID показывают одинакового родителя SCM у обеих
служб, а не запуск Hop внутри Amnezia. Установленный старый EXE имел ошибочный
FileDescription/ProductName AmneziaVPN Service и OriginalFilename AmneziaVPN-service.exe.

## Итоговая проверка кандидата перед обновлением основного ПК

Повтор 884eb4c14723489e9c5d8c84766edb34 выявил отдельный дефект повторного stop:
после успешной очистки RoutedAwgProtocol следующий проход внешнего таймера снова
вызывал stopAfterFailure дочернего AWG. Его локальный флаг владения guard оставался
установлен, поэтому защита временно создавалась заново. Нативная регрессия повторных
stop/stopAfterFailure сначала упала, затем прошла после исправления: завершённая
очистка со снятой защитой больше не вызывает дочерние stop и не меняет guard.
