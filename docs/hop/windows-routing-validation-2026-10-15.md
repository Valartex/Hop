## Общий компилятор

`trafficPolicy` компилирует упорядоченные доменные/IP/GeoIP/GeoSite правила
в Direct/VPN/Block, не разрешая GeoSite в статические IP. Неизвестные/повреждённые
правила отменяют весь снимок. Пределы: 512 правил, 2 МиБ исходной политики,
32 МиБ раскрытых категорий. Reverse-match пока отклоняется явно.
Для доменов формируются FakeDNS и sniffing; настоящий DNS всегда идёт через VPN.
Используется IPOnDemand: завершающее правило по умолчанию не подавляет IP-проверки.
Сгенерированная конфигурация принята настоящим Xray в нативном тесте.

VM `68a33160626448f49fc926911fb94386`: TCP через SOCKS Xray → нативный AWG прошёл.
VM `3bd18b0c706c45c5b87970933566ce62`: домен VPN получил HTTP 204, домен Block —
HTTP 0 / Qt 2; оба разрешаются тестовым DNS в один IP. UDP echo в этих запусках
шёл непосредственно через AWG, а не через общий frontend. FakeDNS в TUN этим
ещё не доказан. Общий frontend пока подключён только к VM-пробе, не к GUI.

## Обновление DAT

Источники/ETag/Last-Modified/расписание сохраняются в SecureQSettings проверяемой
записью. Проверка раз в сутки, exponential backoff и Retry-After. Локальный импорт
снимает автоматическое обновление соответствующего набора. Хэш кэша проверяется
перед условным запросом и при 304. Повреждение, обрыв pipe и отказ записи расписания
покрыты нативными тестами. DAT проходит по бинарному ограниченному pipe (64 МиБ),
без Base64-копий большого ответа. Подписки сохраняют прежний предел 4 МиБ.

## Direct: обязательная граница

Автоматическая проверка отклонила предложенное широкое разрешение TCP/UDP для
службы на физическом адресе/адаптере. Отклонённая команда не исполнялась.
Вместо неё реализована отдельная разрешающая запись на каждый выбранный Direct-сокет:
AppID Hop-service, физический интерфейс, исходный адрес, удалённый IP, порт и протокол.
Фильтр динамический, снимается при Close/ошибке dial/stop/аварии службы; предел 512.
UDP не может расширить назначение без нового выбора маршрута. VPN-выход не запрашивает
Direct-разрешение. Ошибка удаления закрывает весь динамический набор (fail-closed).

Для этого собран `hop/native/xray` на основе GPLv3 amnezia-xray-bindings v1.4.0
с исходниками и закреплёнными go.mod/go.sum. Новый callback регистрируется один раз;
повторные подключения не накапливают копии контроллера. Четыре Go-теста lifetime,
ошибок, отказа и UDP-границы прошли. Системная приёмка этих фильтров ещё идёт.
Пакет с новым ядром подготавливается `stage-windows.ps1 -PolicyCore`; обычный stage
пока оставляет upstream bindings. Нельзя заменять пакет во время задания VM.

### Полный TUN после исправления uplink

Причина отрицательных проб: on-link gateway `0.0.0.0` при повторном создании обхода
Xray выбирал default route самого AWG. В полной AllowedIPs-конфигурации это давало
петлю внешнего UDP (отрицательный `8afbe426f41b46488378522c86a41666` сохранён).
Составной клиент больше не дублирует обход native AWG; монитор AWG исключает также
Hop-TUN из кандидатов внешнего интерфейса. Общий Windows router обрабатывает on-link
обход одиночного IPv4 явно по исходному физическому интерфейсу.
