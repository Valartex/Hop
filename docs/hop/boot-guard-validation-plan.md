# Проверка защиты после перезапуска Windows10 VM

Цель — проверить, что постоянные фильтры Hop загружаются Windows после аварийного
перезапуска и продолжают блокировать защищаемый путь, сохраняя разрешённый Direct.
Продуктовый MSI не меняется. Тестовый probe запускается только ограниченным
Hop-VM-Agent после проверки VirtualBox.

1. Через IPC установленной службы включить guard без активного VPN: разрешён
   только Direct1.1.1.1/32, защищаемый1.0.0.1 заблокирован. Проверить оба пути.
2. Сохранить в общей папке GUID собственных постоянных фильтров, их количество,
   время и uptime гостя. Секретов и VPN-конфигурации файл не содержит.
3. Probe ожидает перезапуска60секунд. Если его нет, снимает guard и помечает
   подготовку как expired; агент также выполняет штатную очистку в finally.
4. После явного разрешения пользователя выполнить аварийный reset только VM
   `b79c0594-8e7d-42f6-85b6-3b9784efdb1c`. Такой reset может потерять несохранённые
   данные внутри гостя, поэтому этот шаг требует отдельного подтверждения.
5. Пользователь вручную запускает новый агент. Первый probe до своей обычной
   очистки проверяет смену загрузки по uptime, точное совпадение GUID фильтров,
   отсутствие DISABLED, положительный Direct и отрицательный защищаемый путь.
   Только после наблюдения выполняется обычная очистка и BootInspect-приёмка.

Автоматическое продление/перезапуск агента, задачи планировщика или новые службы
не создаются. Основной ПК, Amnezia и сеть хоста не перезапускаются и не меняются.
Проверка показывает состояние после загрузки Windows, а не отсутствие любых
пакетов в ранней фазе загрузки до запуска BFE. Последнее требует отдельного захвата.

Первый reset не прошёл приёмку: действующих исходных фильтров не обнаружено.
Обычный stop/start собственной службы сохранил фильтры и Direct/Block.
Второй диагностический reset подготовлен после30секундной выдержки фильтров.
Это проверка гипотезы отложенного сохранения, а не исправление первого результата.
