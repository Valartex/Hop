# Hop — установка на основной ПК, 19 октября 2026

Пользователь запросил перенос для полноценной проверки и подтвердил установку
всего необходимого для работы клиента на основном ПК. Это отдельное разрешение
на локальные файлы и собственную службу Hop; прежняя установка только в VM
больше не ограничивает этот конкретный перенос. Amnezia и её настройки не менять.
GUI и VPN автоматически не запускались; сетевые испытания остаются в VM.

## Установленный комплект

- C:\Program Files\Hop\Hop.exe, версия 0.2.0.2.
- SHA256 efa07f6d9c084f8cc4ff44b84351dfeb5e87c46a42a45a194c037fc5ba86b23d.
- 198 файлов, хэши каждого сверены с подготовленным локальным комплектом.
- Клиент, служба, Xray/AWG, tun2socks, Wintun/tunnel DLL, измерители доступности,
  утилита восстановления только Hop, Qt/VC runtime, плагины, DAT и лицензии.
- VM-агент, сценарии, тестовые probes, QtTest и старый MSI не переносились.
- Источник: build/windows-local-0.2.0.2, сформированный из актуального
  build/windows-test. LOCAL-RUNTIME-MANIFEST.json содержит точный перечень/хэши.
- Служба Hop-service: Automatic / LocalSystem, зависимости BFE и nsi,
  бинарник строго C:\Program Files\Hop\Hop-service.exe, состояние Running.
- Проверено наличие слушающего IPC local:HopVpnIpcInterface. Это проверка
  доступности pipe без отправки команд службе, не проверка VPN-подключения.
- Каталог Program Files и служебный EXE принадлежат группе Administrators;
  обычным Users наследуется ReadAndExecute. Wintun DLL имеет действительную подпись;
  tunnel.dll не подписан как обычная DLL. Компоненты туннеля запускаются по запросу
  при подключении, отдельный туннель/адаптер во время установки не создавался.
- Ярлыки Hop на рабочем столе пользователя и в меню «Пуск» указывают на эту копию.

После установки хэш состояния маршрутов/DNS совпал с исходным. Состояние,
режим запуска и PID служб Amnezia совпали. Перезагрузка не потребовалась.
Не запускали Host GUI, соединение VPN или миграцию пользовательских настроек.
Подписки/закрытые ключи/правила из VM в локальный профиль не переносились;
пользователь добавляет подписки в локальной копии либо отдельно запрашивает перенос.

Результат установки: .research/local-hop-install-result.json, completed=true,
ipcListening/networkUnchanged/amneziaServicesUnchanged=true.
Повторная проверка вне AppContainer подтвердила Running/Auto/LocalSystem,
PID 28604, точный путь службы и цель ярлыка; GUI-процессов Hop нет. Внутри
AppContainer Get-Service ошибочно не видит Hop-service — не считать это отсутствием
установки и не пытаться создавать службу повторно по такому результату.
Временные вспомогательные скрипты подготовки/размещения находятся в .research;
это разовая установка по запросу, работа над продуктовым MSI не возобновлялась.
