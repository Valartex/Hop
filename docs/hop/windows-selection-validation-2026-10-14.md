# Каталог и переключение локаций Windows, 14 октября 2026

Проверки выполнялись только в Windows 10 VirtualBox. Amnezia на основном ПК не отключалась.

## Реализовано

`LocationCatalog` объединяет локации HTTP-подписок и страны Amnezia API.
Идентификатор API-локации состоит из UUID сервиса и точного кода страны провайдера;
код ISO хранится отдельно. В настройки сохраняются ручной/фиксированный/автоматический
режим, порядок отдельных локаций и стран, исключения и ручные коды ISO.
Страна включает соответствующие локации всех сервисов. Названия городов не используются
для угадывания страны; у VLESS учитывается флаг в подписи.

`SelectionSession` сериализует попытки и ждёт подтверждённой очистки прежнего туннеля.
Токены поколений исключают обработку старых результатов. Рабочая локация сохраняется;
перестановка приоритетов сама по себе её не переключает. Отключённая физическая сеть
приостанавливает проверки. При исчерпании пула повторные попытки идут с задержкой.

`LocationCoordinator` выполняет подготовку API в отдельном процессе и проверяет DNS
через собственный TUN с проверкой интерфейса маршрута и привязкой исходного IP.
Проверки доступности не означают измерение пропускной способности.
Каталоги API обновляются раз в 6 часов; общий «Обновить» обновляет оба вида подписок.

## Доступ к управляющим API

Вместо постоянного разрешения Hop.exe используются динамические WFP-разрешения
на точный IP, порт, протокол и AppID установленного Hop.exe. Срок — 45 секунд
по монотонным часам; динамическая сессия удаляется при аварии службы.
DNS-разрешение относится только к адресам DNS этой сети и процессу Hop.exe.
Обычный системный DNS других процессов не получает общего исключения.

Для HTTPS-подписки собственный resolver выбирает адрес, сертификат проверяется
по исходному имени. HTTP/1.1 сохраняет исходный Host при соединении по IP.
Перенаправления проверяются отдельно; размер ответа ограничен. Секретные URL
и конфигурации передаются подпроцессу через анонимные каналы.

VM `647034c9948847f5a07598fa17af48ec`: проверены точные четыре условия разрешения,
отказ другого процесса на том же IP/порту, обновление постоянной политики при
действующем разрешении, удаление по TTL и при аварии своей службы. После удаления
динамического разрешения сохранялись 11 постоянных правил и блокировка трафика.

VM `3a717e9ff8814e08bd4376610c22ff58`: собственное разрешение домена под защитой,
53 страны Amnezia и 62 записи BlancVPN; повторный запрос с защищённым SDK-кэшем
успешен за 8424 мс. Кэш передаётся по анонимным каналам, хранится зашифрованным
и исключён из пользовательского экспорта настроек.

VM `e4fe142b8aed4e17a1b0c3ebdaa05c49`: повторены SOCKS/TUN HTTPS, Direct,
аварии туннеля и службы, восстановление доступа и жизненный цикл SCM. Все этапы
успешны, временные тестовые службы удалены.

## Время жизни IPC и сохранение подписок

В Windows Hop привилегированный IPC-процесс принимает только `tun2socks.exe`,
собственный `tun://Hop-TUN` и SOCKS на `127.0.0.1`. Произвольные native arguments
отключены, рабочая папка фиксирована. AWG запускается отдельным штатным SCM-путём.
Эта граница не предоставляет через IPC запуск OpenVPN или CertUtil.

Неиспользованные IPC-объекты ограничены восемью и удаляются через 30 секунд;
завершённые — через 5 секунд. Лямбды не удерживают дескрипторы через циклические
shared-pointer-ссылки. При потере владельца завершается только соответствующий дочерний процесс.
VM `01ca5880bdba416e981eb62013fc680c`: лимит, отказ постороннего запуска и освобождение
неиспользованных слотов подтверждены. VM `6b366e65963d4098988fef7a7738e867` повторил
полный BlancVPN/Direct/авария/SCM-тест с этой службой. VM
`9c3bdd92151f43f3946830a9ba368d4b` повторил успешный AWG → VLESS с 15 сохранёнными
правилами и нулём правил после ручного отключения.

Ранний повтор `f66390c5329741d0a9bd4bc2e0bf3471` получил Qt TemporaryNetworkFailure
при первом TUN-запросе после успешного SOCKS. Без изменения сборки следующий полный
запуск прошёл. Это не считается доказательством приёмки физических переходов сети.

Снимок HTTP-подписки сначала сохраняется через проверяемый `QSettings::sync`,
затем публикуется в модели. При отказе записи старые записи, выбор и сохранённый
снимок остаются прежними; сигнал успешного обновления не отправляется. Нативный тест
инъецирует отказ записи, другой тест проверяет успешную запись независимым экземпляром
QSettings. Все шесть нативных наборов прошли после этих изменений.
Аварийное выключение Windows во время записи ещё не проверялось.

## Что этим не доказано

Не завершены применение DAT-маршрутов, общая доменная маршрутизация AWG/VLESS,
утечки DNS/IPv6 при всех режимах, сон/смена сети/BFE/перезагрузка и физическая
приёмка GUI. Успешный переход между двумя локациями не заменяет эти проверки.
