# Интерфейс, логика и перенос Hop

Проверено по текущему checkout 20 октября 2026. Реализация и сборка — только
Windows; сборки остальных платформ не выполнялись. Это оценка переноса,
а не подтверждение их работоспособности.

## Что изменено при рефакторинге

- `ui/controllers/connectionsPageController.*`: единая точка действий страницы
  подключений — отдельная проверка, обновление и локальное удаление подписки,
  объединение результатов проверок, доступность действий. Контроллер не включает
  QML/Quick и не открывает окон. QML отображает состояние и запрашивает действия.
- `PageHomeHop.qml`: удалены выбор API/native-проверки и выбор способа обновления
  подписки. Открытие статистики осталось отдельным действием. Удаление подтверждает
  пользователь; повторная проверка состояния выполняется в C++, а не только через
  disabled-кнопку. При соединении или обновлении удаление недоступно.
- `EndpointHealthController`: общая постановка одиночной и групповой проверки
  в очередь вместо повторяющейся проверки конфигурации/помощника/состояния AWG.
  Сохранены предел двух процессов и последовательная AWG-проверка.
- `SecureServersRepository`: единая публикация проверяемого снимка для обновления
  и удаления. При ошибке сохранения список в памяти не изменяется. Старый
  `removeServer` оставлен ради совместимости его потребителей и сигналов.
- `LocationHistoryStore`: отдельный ограниченный файловый компонент. Он не знает
  VPN-конфигураций, ключей, протоколов и QML. Чтение/запись последовательны в
  фоновом задании; график и статистика отделены от хранения.
- Убраны повторные явные включения `.h/.cpp` для `exportController` и
  `amneziaApplication` в CMake. Два включения обработчика уведомлений оставлены:
  они находятся в взаимоисключающих ветках desktop и macOS Network Extension.

## Насколько отделён интерфейс

Разделение есть, но оно неполное. Каталог и машина выбора локаций, парсеры подписок,
GeoIP/GeoSite, политика маршрутов и история реализованы на C++/Qt Core/Network;
в `core/locations` и `core/routing` нет include QML/Quick. Состояние выбора
`SelectionSession` отделено от исполнителя сети `LocationCoordinator`. Новый
контроллер действий уменьшает знание страницы о конкретном провайдере.

Сохраняются зависимости от Qt и состава приложения. `CoreController` одновременно
собирает зависимости, подключает сигналы и регистрирует QML context properties.
Страницы обращаются к глобальным контроллерам. Исполнители используют процессы,
репозитории и IPC. Поэтому заменить QML другим UI нельзя одной настройкой сборки:
потребуется новый слой интеграции и тестирование жизненного цикла.

Для нового интерфейса удобнее постепенно получать состояние и команды через
узкие контроллеры страниц. Полное переписывание composition root в эту правку
не включено: оно значительно расширило бы согласованный объём.

## Неиспользуемые части

Проведены проверка списков сборки, ссылок новых страниц/компонентов, границ
модулей и повторяющихся сценариев затронутого кода. Это не доказательство
отсутствия любого мёртвого кода во всём upstream и не прогон clang-tidy.

В проекте остаются OpenVPN/IKEv2, self-hosted управление и прежние страницы Amnezia.
Они имеют потребителей в общих моделях, импорте/настройках и платформенных ветках.
Отсутствие прямой кнопки в стартовой странице Hop недостаточно для удаления:
часть страниц загружается по PageEnum, часть нужна сохранённым форматам и другим ОС.
Массовое удаление этих подсистем требует отдельного согласования состава продукта.

Тестовые VM-сценарии также не следует путать с функциональными модулями клиента.
Они нужны для проверки уже согласованного поведения; их выделение в отдельную
тестовую сборку можно рассматривать отдельно, без изменения VPN-поведения сейчас.

## Что мешает переносу

| Часть | Повторное использование | Что остаётся сделать |
|---|---|---|
| QML-компоненты, стили, каталог и поиск | Значительная часть общая | Подключить Hop-навигацию и проверить компоновку, ввод, жизненный цикл на целевой ОС |
| Импорт, подписки, DAT, приоритеты, история | Qt-код преимущественно общий | Проверить пути, хранилище секретов, фоновые обновления и доступность помощников |
| Windows WFP/служба/маршруты | Реализация Windows | Адаптеры защиты и маршрутов для каждой ОС; WFP туда не переносится |
| Проверки доступности | Контракт и расчёт общие | Заменить Windows `.exe`-помощники подходящим исполнителем |
| Android | В upstream есть контроллеры и VPN-интеграция | Связать новый Hop-сеанс с VpnService, защитой сокетов, DNS/маршрутами и фоновой службой |
| iOS/macOS NE | В upstream есть Swift PacketTunnelProvider и реализации Xray/WireGuard | Выполнять транспорт и маршрутизацию в Network Extension, согласовать IPC, права и восстановление |
| Linux/macOS desktop | В upstream есть платформенные ветки и служба | Подключить новые маршруты/защиту Hop, права TUN, сетевые события и упаковку |

Конкретные привязки: создание Hop-каталога/сессии сейчас находится внутри
`Q_OS_WIN` в CoreController; Go AWG-помощник собирается с GOOS=windows;
`LocationCoordinator` ожидает `hop_tunnel_probe.exe`; `controlPlane::permit`
на других ОС пока возвращает false. `PageStart.desktopHop` включается для Windows.
Следовательно, наличие пяти платформ у исходной Amnezia не означает готовность
всех новых возможностей Hop на этих платформах.

## Qt или Flutter

Для текущего проекта рекомендую сохранить Qt/QML. Перенос интерфейса на Flutter
потребует переписать страницы и подключить C++/Go/платформенные исполнители через
FFI, platform channels или плагины. Работа над VPN-службой, TUN, DNS, защитой
трафика и восстановлением останется. Доказательств выигрыша Flutter по ресурсам
для этого клиента нет: сопоставимые прототипы не измерялись.

Flutter имеет смысл обсуждать при отдельном решении полностью менять UI/команду
разработки. В текущем состоянии он добавит миграцию и второй стек интеграции;
сам по себе не упростит наиболее сложную часть — системный VPN.

Официальные источники:

- [Qt 6.10: поддерживаемые платформы](https://doc.qt.io/qt-6.10/supported-platforms.html).
- [Flutter: вызов платформенного кода](https://docs.flutter.dev/platform-integration/platform-channels).
- [Android VpnService](https://developer.android.com/reference/android/net/VpnService).
- [Apple NEPacketTunnelProvider](https://developer.apple.com/documentation/networkextension/nepackettunnelprovider).

Порядок будущих работ по переносу здесь описан для оценки; реализация других
платформ и новые этапы не начинались.
