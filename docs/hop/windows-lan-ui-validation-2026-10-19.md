# Hop 0.2.0.3 — LAN, уведомления и элементы интерфейса

Статус на 21:50 МСК: окончательная 0.2.0.3 установлена в VM, проверки LAN и
AWG GUI прошли. Основной ПК продолжает работать с установленной 0.2.0.2;
запрошено штатное закрытие GUI для замены двух EXE. Его автоматически
не отключали/не обновляли. Amnezia и маршруты/DNS хоста не менялись.

## Замечания и изменения

1. Уведомления используют QCoreApplication::applicationName вместо литерала
   AmneziaVPN; QSystemTrayIcon получает значок Hop из ресурсов. Для собственного
   AUMID Hop.Desktop задаётся DisplayName Hop в HKCU, по обычной схеме
   [регистрации отображаемого имени Windows](https://github.com/microsoft/WindowsAppSDK/blob/main/dev/AppNotifications/AppNotificationUtility.cpp).
   Подписи собственных WFP-правил/службы туннеля тоже используют имя приложения.
   Аудит Windows-маршрута UI не нашёл AmneziaVPN в страницах Hop. Имена провайдера
   и протокола, копирайты, форматы ключей и отложенные legacy-платформы не переименованы.
2. На хосте только чтением установлено: 192.168.1.1 выбирает on-link маршрут
   192.168.1.0/24 через Wi-Fi, а не Hop-TUN. TCP/80 при активном Hop не подключился.
   Обычные широкие маршруты TUN проигрывают этому /24; приложение обходит Xray,
   а WFP запрещает физический сокет без Direct-разрешения ядра.
   Исправление: при запуске общего frontend на Windows подсеть IPv4 uplink
   перехватывается двумя дочерними префиксами через Hop-TUN. Исходная LAN-строка
   не заменяется. Обычная политика VPN/Direct/Block применяется и к LAN;
   новые разрешения WFP не добавляются. Собственные строки учитывает существующий
   журнал маршрутов и удаляет при завершении сессии. Серверный /32 сохраняется.
   Перехват относится к подсети выбранного uplink, не обещает проверку всех
   возможных вторичных интерфейсов и адреса, совпадающего с VPN endpoint.
3. Общая HopScrollBar: контрастный бегунок 8 px, дорожка 12 px, без исчезновения
   при бездействии, видна при переполнении. Строки списков оставляют место справа.
   Применена к локациям, маршрутам, автопулу, категориям DAT и настройкам.
4. Дорожка свитчера уменьшена до 40×22, строка остаётся высотой 36.

## Системная проверка

hop/scripts/test-lan-vm.ps1 поднимает только loopback HTTP-стенд на хосте.
VM видит его через NAT 10.0.2.2. В ограниченное задание передаётся лишь порт;
ключ BlancVPN остаётся в памяти уже запущенного вручную агента.
Изолированный сценарий использует полный PRIVATE из поставляемого GeoIP и
ручной режим выбора локации. Он проверяет HTTP до подключения, захват LAN
через TUN, HTTP с PRIVATE Direct, отказ после PRIVATE Block, переподключение
при изменении политики, исходный маршрут и HTTP после одного отключения,
очистку фильтров/состояния UI и название уведомления Hop. Он не выдаёт
успешность LAN за подтверждение внешнего подключения BlancVPN.
Обычные VM GUI-проверки используют отдельный
QStandardPaths test-mode DAT-кэш, не перезаписывая рабочие наборы пользователя.
