# AmneziaWG 3.1 в Windows 10 VM

Проверено 14 октября 2026. Системный VPN на основном ПК не изменялся.
Все службы, адаптеры и WFP-фильтры Hop создавались только в VirtualBox.

## Подписка Amnezia

После освобождения пользователем слота API успешно выдала конфигурацию AWG 3.1.
Прогон `652c54b34e384bd1be019eb3b9e568b2` завершился с `exitCode: 0` и
`recoveryExitCode: 0`:

- API bootstrap: 0, CAPTCHA не потребовалась;
- присутствует HeaderProtectionKey;
- IPv4-адрес адаптера Hop достиг состояния Preferred;
- HTTPS по IPv4: HTTP 204 / Qt 0;
- HTTPS с разрешением домена: HTTP 204 / Qt 0;
- явный UDP DNS-запрос к настроенному DNS: корректный ответ;
- штатное отключение подтверждено службой после очистки;
- отзыв конфигурации временной установки: 0.

Ключ подписки, приватные ключи и конфигурация не сохранялись в файлах.
Тест использовал репозитории с отключённой персистентностью; передача ключа
в VM выполнялась через одноразовый RSA-OAEP / AES-GCM конверт.
Отзыв затронул только новый UUID тестовой установки.

Первый прогон после освобождения слота (`d5fc087e2bf84a2997efa1f513740afa`)
успешно выполнил оба HTTPS-запроса, но завершился ошибкой из-за UDP-пробы.
Причиной оказался тестовый QUdpSocket без явного bind для приёма ответа.
Этот прогон не считается успешным. Его временная конфигурация также отозвана.

## Локальный стенд

Прогон `0f1b42e9129240b7b2f8fe8f00e63bd4`: TCP HTTP 204, UDP echo,
штатное отключение и восстановление — успешно.
Повтор на текущей сборке после исправлений очистки/IPC:
`58bf453d74454ae689902914fe573016`, оба кода завершения 0.
Одноразовый peer работает через пользовательский netstack и слушает UDP только
на loopback основного ПК. Адаптеры, маршруты и firewall хоста не изменяются.
Версия Go-ядра совпадает с Windows DLL: `v3.1.20260814`.

До исправления готовности адаптера локальный handshake завершался, но TCP
получал Host unreachable: SCM уже сообщала Running, а адрес ещё был Tentative.
Служба теперь ограниченно ожидает Preferred и отклоняет Duplicate/тайм-аут.

## Защита конфигурации службы

SCM получает путь к зашифрованному одноразовому файлу вместо приватного ключа
в командной строке. Файл использует DPAPI machine scope и DACL для SYSTEM и
Administrators, удаляется автоматически после старта. Проверены round trip,
отсутствие открытого тестового секрета в содержимом файла и автоматическое удаление.
Исправлена передача Unicode-аргументов дочерней службе для профиля пользователя
с кириллицей в пути.

## Аварии и постоянная защита

Прогоны `53a4b51443bc4c9fa41a2313ee265116` и
`f028b88d88cc428380f17cc402fd5ce3` — `exitCode: 0`,
`recoveryExitCode: 0`. Использовался только локальный одноразовый peer;
подписка Amnezia не расходовала слот.

После TCP HTTP 204 и UDP echo принудительно завершён процесс собственной
AWG-службы. Клиент обнаружил аварию (603), сохранились 16 WFP-фильтров,
защищённый HTTPS заблокирован (HTTP 0 / Qt 99), Direct HTTPS вернул HTTP 200.
Затем завершён процесс основной тестовой службы Hop: защищённый HTTPS
по-прежнему заблокирован, Direct HTTPS вернул HTTP 200.
Снятие только собственной защиты гостевой утилитой восстановило HTTP 200
по ранее защищённому адресу. Проверка контрольного адреса до включения VPN
также возвращала HTTP 200.

Ошибки остановки/удаления службы больше не подтверждаются как успешное
отключение. Потеря IPC сохраняет защиту. Нативный регрессионный тест проверяет
ожидание ACK, обработку ошибки до disconnected и отсутствие повторного
уведомления об отключении.

В более раннем прогоне Direct после завершения основной службы один раз
завершился тайм-аутом. Следующие успешные прогоны прошли без повторного запроса.
Тест допускает один явно записанный повтор только для тайм-аута разрешённого
запроса; блокировка должна давать Qt 99 и не засчитывается по тайм-ауту.

Функция GUID в AWG Windows включает имя интерфейса даже в режиме Fixed GUID.
Имя Hop отделяет его GUID от имени Amnezia; модификация DLL для этого не нужна.
[Исходная реализация](https://github.com/amnezia-vpn/amneziawg-windows/blob/v3.1.20260814/deterministicguid.go).

## Границы результата

Базовое системное подключение AWG 3.1 подтверждено в текущей сети.
Это не приёмка всей Windows-версии: остаются интеграция DAT-маршрутов,
автоматическое переключение локаций, установщик и проверка GUI через SCM,
расширенные DNS/IPv6, BFE/перезагрузка и ресурсные измерения.

На этой же сборке контрольный BlancVPN/VLESS-прогон
`92850dc1f11b44f890cf112e278d4ae9` завершился с обоими кодами 0:
SOCKS/TUN HTTPS, DNS, Direct, сохранение блокировки после очистки и аварии
активной службы, восстановление, регистрация/старт/остановка/удаление тестовой
службы SCM. Проверка GUI через установленную службу по-прежнему отдельная.
