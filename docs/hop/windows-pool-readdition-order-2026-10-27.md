# Порядок повторного добавления локаций в автопул

0.2.0.19. Причина: toggleMembership помечал отдельную локацию как excluded,
сохраняя её запись в priorities. Повторное добавление только снимало excluded,
поэтому возвращалось прежнее место. Два новых регрессионных сценария воспроизвели
ошибку на прежней реализации: .research/pool-0219-before.txt.

Теперь удаление отдельной локации убирает её индивидуальную запись приоритета,
повторное добавление ставит её в конец. При редактировании индивидуального пула
также убираются скрытые индивидуальные позиции исключённых локаций, сохранённые
прежними версиями. Остальные исключения остаются, так что удалённая локация
самопроизвольно не становится кандидатом. Обновление порядка и исключений
сохраняется одним save/сигналом policyChanged.

Пул по странам сохраняет семантику групп: страна остаётся единым приоритетом,
отдельную локацию можно исключить и вернуть в её группу. Режимы всех локаций
продолжают использовать порядок общего списка/задержку и собственные исключения;
изменение порядка индивидуального пула их не переопределяет.

Проверки: очистка и повторное добавление в другом порядке, приоритеты 1/2/3,
повторное добавление одной локации при непустом пуле, загрузка сохранённого
порядка, старые исключённые записи и сохранение групп/режимов всех локаций.
Каталог и SelectionSession проверяются изолированно, без реальных VPN.
