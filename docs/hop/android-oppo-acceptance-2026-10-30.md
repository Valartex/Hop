### Повторная диагностика на Билайне

- Без VPN по мобильной сети ya.ru возвращал HTTP 302, а прямой TCP-запрос
  к контрольному серверу example.com завершался тайм-аутом.
- У импортированных записей BlancVPN Extra Whitelist2 один входной IP.
  По Билайну входной узел принял TLS и вернул HTTP 101 на запрос WebSocket.
  В Hop интерфейс tun0 был привязан к мобильной сети. Внутри туннеля TLS
  к example.com с заранее полученным IPv4 и проверкой сертификата завершился
  тайм-аутом. Обычный HTTPS-запрос к example.com завершился ошибкой DNS.
  Отказ воспроизводится и при исключении DNS из проверочного запроса.
- Штатный BlancVPN с выбранным Амстердамом поднял мобильный VPN-интерфейс.
  За время сравнительной проверки контрольный HTTPS-запрос также не прошёл.
  Точная причина отказа после входного WebSocket-соединения не установлена.
- На Wi-Fi профиль «Германия, Extra Whitelist2» вернул HTTP 200 и показал
  выходной IP в Германии. После изменения проверки Hop подтвердил этот
  профиль по HTTPS 204 через Android VPN. Проба применяется только к Xray
  без правил маршрутизации. Для раздельного туннелирования и AWG оставлена
  проверка DNS, чтобы ответ через Direct не подтверждал сам туннель.
- При подготовке «Гренландии [обход БС]» на Wi-Fi Amnezia вернула код 1108
  и сообщила, что занято 7 из 7 конфигураций. Hop теперь прекращает ручную
  попытку с этой ошибкой. Автовыбор сохраняет возможность проверить другие
  локации. Для теста передачи трафика нужен свободный слот или готовый профиль.

Сборка с исправлениями установлена на Oppo.
SHA-256 APK `766c853e5a6368f1b2d0f5a59b784891bdae80fd90e2d0efab3dac91c19bd368`.
SHA-256 AAB `1c8c801e297f1b9e2fd714a75b6e0f276559b6c453bd94be6f9f4c04c0b2934b`.
Проверены подпись, выравнивание APK, 16-КБ выравнивание библиотек,
`HopSelectionSession` и `HopNativeDashboard`.

### Повторная проверка BlancVPN после исправлений Hop

В профиле «Германия, Extra Whitelist2» задан TLS fingerprint `firefox`.
Hop терял его при импорте TLS/WebSocket. Импорт исправлен, старые
подписки заново обрабатываются при обновлении. На Android локальный
SOCKS-вход теперь запускается до публикации VPN-интерфейса. Проверка
полного туннеля принимает HTTPS-ответ от одного из двух контрольных узлов.

С выключенным Hop отдельный тест WebSocket-входа профиля на Oppo
подтвердил TLS во всех попытках. По Билайну вход вернул три HTTP 502
и один HTTP 101. По Wi-Fi повторилась та же пропорция. Это сбои на
пути до WebSocket-входа или на самом входе, независимо от Hop.

На итоговой сборке с выключенным Wi-Fi и раздельным туннелированием
провели шесть серий через один VPN-интерфейс Hop.

| HTTPS-запрос | Успешно из 6 |
| --- | --- |
| example.com | 4 (HTTP 200) |
| Cloudflare Trace | 3 (HTTP 200, выход DE) |
| www.wikipedia.org | 3 (HTTP 200) |
| Google generate_204 | 5 (HTTP 204) |

Первая серия завершилась тайм-аутами, в последующих были отдельные
ошибки TLS. За время серии Hop сохранил тот же VPN-интерфейс. После
проверки VPN отключён, Wi-Fi и раздельное туннелирование включены.
Прошли `XraySerializationTest` и `HopHttpSubscriptions`.

VPN-интерфейс. Первую успешную серию всех четырёх HTTPS-запросов
завершили примерно через 11 секунд после включения мобильных данных.
Повторная серия также вернула HTTP 200. Cloudflare показал выход NL,
внешний IPv4 Яндекса совпал с замером без VPN.

### Восстановление «Гренландии [обход БС]» при заблокированном экране

На итоговой сборке с меню ☰ четыре контрольных HTTPS-запроса
прошли до блокировки Oppo. Wi-Fi был выключен, раздельное
туннелирование включено. Мобильные данные Билайна отключили
на 12 секунд после подтверждения Android `Dozing` и активного
экрана блокировки. Сеть по умолчанию и VPN-интерфейс исчезли.

С включением мобильных данных Hop автоматически восстановил ту же
локацию на новом VPN-интерфейсе. В первой серии Cloudflare Trace
вернул HTTP 200 с выходом NL, Яндекс Интернетометр вернул HTTP 200
с прямым IPv4, два остальных запроса завершились тайм-аутом.
Примерно через 33 секунды после включения данных все четыре запроса
(включая example.com и Wikipedia) вернули HTTP 200. Android
подтвердил блокировку до и после замеров. После теста VPN остановили,
Wi-Fi вернули, экран оставили заблокированным.

## Последовательность приёмки

1. Установка, запуск, журналы ошибок и отображение на реальном экране.
2. Навигация, импорт подключений, резервная копия и импорт DAT через выбор файла.
3. VLESS/AWG: фактические DNS, TCP/UDP и работа маршрутов/Direct.
4. Отмена, повторное подключение, автопул, сворачивание и возврат, блокировка экрана.
5. Смена Wi-Fi/мобильной сети, потеря сервера и восстановление.
6. Подготовленные специальные профили BlancVPN и Amnezia в ограниченной
   сети Билайна в Брянской области. Результат подтверждают HTTPS-запросами.
7. По желанию пользователя — системные Always-on/lockdown Android. Собственный
   Kill Switch Hop с сохранением Direct согласован как следующий этап.

Источник подключений — установленный Windows Hop. Для проверки доступен Wi-Fi,
мобильные сценарии проверяются на Билайне.
