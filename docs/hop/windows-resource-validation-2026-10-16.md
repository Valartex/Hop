# Измерения ресурсов Windows 10 VM

Проверенный MSI: `714aceed40b84a450c106ea9d9d956e8029da510eae9c0243f09993d9baeb33a`.
Windows 10 19045, VirtualBox, 1 CPU, 8 ГиБ RAM. Основной ПК и Amnezia не менялись.

Измеритель каждую секунду читает счётчики процессов с точными путями установленного
Hop.exe, Hop-service.exe и tun2socks.exe. Учитываются основная служба, AWG tunneldaemon,
GUI и кратковременные процессы того же установленного клиента, попавшие в выборку.
Пики ниже — максимальная одновременная сумма, а не сумма отдельных пиков процессов.

| Протокол | Время сценария | Пик рабочего набора | Пик private bytes | Средний CPU одного ядра |
| --- | ---: | ---: | ---: | ---: |
| VLESS Reality | 28,08 с | 191 МиБ | 224 МиБ | 6,8% |
| AWG 3.1 + общий Xray frontend | 67,66 с | 270 МиБ | 316 МиБ | 11,9% |

VLESS: `bb74311dbfd54493b42b908d60a0f0e1`; AWG: `aba2c94048b544ce927887fcbdbfb9d1`.
Оба exit0/recovery0, sampler complete=true/issues=[]: импорт, подключение, изменение
доменного правила, переподключение, Block/Direct и одно отключение с guard0/UI clear.
Обычный пользовательский token, ACL журнала закрыт для GUI, QML warnings0.

AWG дополнительно передал 4 МиБ с проверкой SHA256 за 5,985 с — 5,606 Мбит/с на
локальном стенде через NAT VM. Это не максимальная скорость протокола или провайдера.

Средний CPU включает запуск и переключение туннелей, у AWG также передачу файла.
Это не connected idle; разная нагрузка и продолжительность не позволяют прямо
сравнивать эффективность протоколов по двум процентам. Рабочие наборы процессов
повторно учитывают общие страницы DLL; private bytes — отдельная метрика выделенной
памяти. Короткие процессы и пики между секундными выборками могут быть пропущены.
Для GUI отдельно получено 0% одного CPU в трёхсекундном connected idle у обоих
протоколов; общий idle всех процессов и батарея этим не измерены.

Старые результаты sampler complete=false не использованы. Причина error6 оказалась
в test-only debugger: дескрипторы процесса/потоков из DebugEvent закрывались слишком
рано, затем Windows могла повторно закрыть уже переиспользованный номер. Удалён
ранний CloseHandle; image/DLL handles закрываются явно, остальные после EXIT закрывает
ОС. Это соответствует [WaitForDebugEvent](https://learn.microsoft.com/en-us/windows/win32/api/debugapi/nf-debugapi-waitfordebugevent).

`0f228135f3ff475c97723fb78856e839` сохранён как отрицательный GUI-прогон:
DirectBeforeEdit=false; повтор на том же MSI `bb743...` прошёл полностью.
Все результаты, BUILD-MANIFEST и MSI-HASH сохранены в `.research/vm-runs/<id>`.
Новые изменения AWG-кандидат проверки после этих прогонов требуют отдельной приёмки.
